# M2-D — Schema, Ledger, Migration and Recovery Contract

## Versions
Recommend additive career schema 4 / registry schema 4 with explicit preview/confirmation of schema 3 -> 4. Preserve schema 1/2/3 read and validation behavior; original M2-C 2->3 maintenance semantics remain untouched. Version lifecycle employee/contract records (suggest version 3), independently discriminated completion/obligation/settlement/failure records, strict command v3 and a distinct 3->4 protected maintenance variant. Keep original outer history/envelope versions only if strict mixed-version dispatch, migration replay and old-import tests prove safe; otherwise STOP for owner review. Do not patch old records with new fields in place.

## Authoritative completion interface
Define strict immutable input: career/profile ID, championship ID, terminal outcome, completed-once state, entrants/contract snapshots, result/rule version, reward breakdown and authority/source fingerprint. An untrusted client JSON blob or UI input is NOT an authority for creating Gold. No production completion producer currently exists. Implement a trusted future-controller adapter contract with deterministic test-only fixture producer; disallow arbitrary production completion submissions and avoid claiming end-to-end playable championships.

## Obligation archive
Obligation ID, career ID, championship/cycle identity, creditor immutable employee ID/name/role snapshot, original assessed integer Gold, paid integer Gold, outstanding balance, and provenance for each payment. Archive creditor snapshots independent of live personnel/contract foreign keys; validate sums and prohibit identity reuse. Expired/terminated/departed employee records may be absent from live registries while historical claims remain valid. No dangling live references.

## Settlement transaction
Pure preview fingerprint includes career, completion identity, rules version, economic/management revisions, source records and reward breakdown. Exact confirmation commits a single protected effect keyed by career+championship, regardless of request ID. One atomic candidate: credit validated income, allocate old claims, assess/pay current wages, update arrears/status, passive recovery, contract term progression, deferred/actual departures, statement and preparation state. Define and test exact order; no partial publication. Distinguish gameplay receipts from maintenance history. Exact retry returns retained result or protected tombstone `ALREADY_COMMITTED` without replay. Mismatch rejects. Preserve M2-C history variants and caps.

## Protected restoration
Existing M2-C overlay retains consumed offers/provenance but cannot by itself reconstruct later debt after restoring older saves. For any known protected settlement, payment, renewal, expiry, departure, emergency grant or failure effect absent from a restored checkpoint: **fail closed** unless a complete validated compatible newer checkpoint exists. Never merely keep tombstone while dropping financial effects; never regrant income, erase wages, regrant emergency driver or replay recovery. Explain blocked recovery with safe fallback/export options. No browser-only scheme can recover unknown facts absent from all supplied history. Test primary, previous-checkpoint, import and manual fallback paths, cross-owner attempts, partial writes and stale fingerprints.

## Atomicity and limits
Retain 1000 gameplay receipts, 2000 protected identities and 8 MiB envelope. Validate strict record shape, ownership, safe-integer arithmetic, balance conservation, no negative Gold, duplicate identity rejection and exact deterministic allocation. No silent compaction/pruning, storage eviction promises or cross-device global authority. All commands must have pure quotes and authoritative reducer checks. Migration never occurs on load/preview/export/navigation.

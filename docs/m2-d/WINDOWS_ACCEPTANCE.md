This is an owner review checklist, not a claim these Windows tests have run.

1. Download/copy `dist/Blood_and_Thunder.html` (or identical `Blood-and-Thunder-Track-Test.html`) to a local Windows folder. Expected size **436032 bytes**; SHA-256 **d1a586a64066b40e40fb540e090c61d48b975d89cecca92e1377aa5b4af3a1a7**. Optional PowerShell: `Get-FileHash .\Blood_and_Thunder.html -Algorithm SHA256`.
2. Back up existing career JSON before opening the new build. Double-click the HTML in a modern browser. Its address should begin `file:///`; no server, Node, npm, internet or adjacent files are required to play. Disconnect network for this check.
3. Verify race setup, track selection, Start/Pause/Step, Strategy Signs, commentary/results, configuration tools and replay still operate. Standalone races are separate from persistent careers.
4. Open Developer tools → Career State / Save Management. If storage is denied, confirm the visible manual-save warning and complete JSON export/import workflow. Browser download requests do not prove that a durable file was saved; locate the actual downloaded file yourself. File moves/browser profiles may change storage scope.
5. Load an accepted M2-C career, or use the existing starting-stable controls to create schema 2, initialize one package, then explicitly migrate to M2-C schema 3. No migration occurs simply by loading a file or opening a panel.
6. Open **M2-D payroll and contract lifecycle**. Click Preview M2-D migration. Cancel confirmation once: Gold, schema and revisions must stay unchanged. Confirm the migration: schema becomes 4, maintenance increases once, gameplay revision/Gold/assets/receipts remain unchanged. No payroll, recovery, income or cycle occurs.
7. Export complete career JSON, save it durably, reload the browser and confirm IDs/Gold/schema/native assets/developer provenance persist. Import the exported JSON through the existing validated replacement workflow; canceled/invalid imports must preserve the previous career.
8. Confirm the panel says **No authoritative championship completion available** and settlement controls are disabled. This is expected: no championship controller/reward producer is included. Running an ordinary race must not charge payroll, create a management cycle or award fabricated prizes.
9. Existing economy tools should remain available for schema 4. Treasury developer adjustment must validate and permanently mark developer provenance. Export before destructive purchases/sales.
10. Optional explicitly synthetic review: `docs/m2-d/evidence/implementation/browser-schema4.json` is a zero-income five-cycle Default payroll fixture, not an ordinary gameplay save. Use a separate browser profile and explicit replacement if inspecting it. Verify 175 G arrears/Default, training/purchases blocked, essential service quotes retained, no false failure for a legal RU. Export prior real careers first. Use a developer treasury edit only if intentionally accepting edited provenance before testing voluntary debt payment.
11. Inspect claims/statements and contract controls. Renew/release/emergency actions must require eligibility and confirmation, not silently run. Driver-only emergency assistance must not add beasts/chariots/gear/Gold/staff. A Failed career must permit export/inspection and reject gameplay changes.
12. If recovery/import reports `UNSAFE_CYCLE_RESTORE`, do not delete protected history to force it through. Keep/export valid current state or raw diagnostic and restore a complete compatible newer backup. Older states cannot erase known wages/lifecycle effects.

Record browser/version, file location, automatic vs manual mode, reload/import/export results and any errors.

# M2-B Windows standalone owner checklist

The managed Linux Chromium environment blocks direct `file://` navigation with `ERR_BLOCKED_BY_ADMINISTRATOR`. HTTP functional checks with the context offline after document loading do not establish file-origin operation. The owner previously confirmed M2-A local testing; that does not accept this changed M2-B build.

1. Download `dist/Blood_and_Thunder.html`. Save existing career exports before testing; retain the old HTML and save backup. No installation, adjacent assets or server should be needed.
2. Double-click the downloaded HTML in a modern Windows browser. Disconnect the network and confirm the viewer, pause/step, track selectors and developer workbench work. Record browser/version and whether the page URL begins with `file://`.
3. Open **Developer → Career State / Save Management → M2-B starting stable and prospective RU**. Set the owner/career names, then create an empty schema-2 career. This replaces a loaded profile only after confirmation; Legacy is never merged. Verify 0 Gold and no assets before initialization.
4. Preview one package. Cancel initialization once; verify nothing changes. Confirm once and verify these grants:

| Package | Gold | Drivers | Beasts | Chariots |
|---|---:|---:|---:|---:|
| Traditional | 1,200 | 1 | 2 | 1 |
| Beastmaster Yard | 850 | 1 | 3 | 1 |
| Mechanist Workshop | 800 | 1 | 2 | 1 |
| Veteran Outfit | 650 | 2 | 2 | 1 |
| Scrappy Underdog | 750 | 2 | 3 | 1 |

5. Verify one Basic property (2 drivers / 0 specialists / 4 beasts / 1 chariot), two neutral equipment records, one descriptive facility, and one assembled eligible RU. The package selector and initialization button must be disabled. Legitimate initialization must not mark the career developer-edited.
6. Refresh at the same file path. If automatic mode is available, verify Gold, IDs, package and assembly persist with no additional grant. Browser storage may vary with browser settings and file path.
7. For Scrappy, select the same beast twice: an eligibility reason appears and commit is disabled. Select the reserve driver and reserve beast, commit, disassemble and reassemble. Gold, fatigue and XP must not change. No race or championship is entered.
8. Export the complete game save and actually save it. Import it, cancel replacement once, then confirm. Verify every asset and assignment survives. Developer race configuration JSON must be rejected as a career save.
9. Export a pre-initialization checkpoint in a separate test career, initialize, then import the older checkpoint into that same session. The grant must remain consumed in protected history: there must be no second initialization. Restore a valid post-initialization export or create a different career to continue. Do not edit JSON to manufacture a recovery grant.
10. Verify browser-denied storage yields **MANUAL** mode, with export and explicit saved-checkpoint acknowledgment required between changes. An export click does not prove durable saving. Private browsing alone may not deny storage; record the actual mode observed, and mark denial testing unperformed if it cannot be reproduced safely.
11. Optionally test a developer treasury adjustment: confirm the persistent edited flag, export/import and verify it survives. A previously edited active career must not be eligible for initialization, even if treasury was adjusted back to zero.
12. Create a distinct new career for each remaining package and repeat relevant checks. Keep all five result records separate.

Report any failure with browser version, protocol, package, save mode, visible notice, reproduction steps and exported diagnostic when appropriate. Do not overwrite your only valid backup. Owner review and approval remain required before merge or later milestones.

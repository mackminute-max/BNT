## Atomic new career

Wizard identity, cosmetic choices, package comparison and review remain in memory. Back/Cancel before final confirmation allocate no slot, owner, asset or unlock. All five current packages are available; source has no additional unlock rule. Unknown/unapproved package IDs reject. No artificial Legacy lock is introduced.

After explicit final confirmation, prepare the existing schema-2 empty factory and its original `career.initialize` transaction in isolated memory, with fixed request/slot/profile/career/transaction IDs. The real `CareerStore.transaction` and pristine guard grant the unchanged package exactly once. Then use the existing complete-backup staged restore/atomic activation to publish the initialized envelope. No durable empty-career head is created along the way; the slot index reserves the destination before authority, as in M1. In-flight/ambiguous saves cannot be cancelled. Retrying the same confirmed request must resume its exact stage or recognize its committed state; a conflicting request cannot replace it. Interrupted stages remain nonplayable until explicit validated recovery.

## Versioned cosmetic metadata

Keep career schema, package definitions, protected history and native assets unchanged. Extend the existing *separate playback/runtime metadata* from version1 to version2, adding a strictly validated presentation object bound to profile/career and the actual protected initialization transaction. It contains only builtin emblem, hex colors and skippable tutorial progress. Existing runtime1 remains byte-compatible and receives no invented cosmetics/tutorial.

Existing IndexedDB generation/read-set commit already preserves runtime atomically; complete backups already carry runtime and its integrity digest. No new backend, logical record key or envelope schema is needed. Both cold loads and restore validate version2 ownership/initialization provenance; metadata updates cannot change the creation identity/cosmetics or silently downgrade/drop it. Legacy career-only JSON stays its original mechanical format and is explicitly labeled as excluding the new presentation metadata; complete backup is the portable cosmetic-preserving format. This is not the separately deferred World Identity/content-pack marker.

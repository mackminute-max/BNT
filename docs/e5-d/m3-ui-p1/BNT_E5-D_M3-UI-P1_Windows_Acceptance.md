1. Verify the HTML against the delivered SHA-256 (`Get-FileHash -Algorithm SHA256` in PowerShell). Copy it to a local folder; disconnect the network. Open it by double-click directly in Windows Chrome, then repeat in Edge. Confirm the address begins `file:///`. No adjacent assets or server should be needed.
2. New Game: enter stable/owner names, inspect all five package comparisons including initial contract wages/duration. Back and Cancel must create no career. Confirm one package once. Repeat with separate careers for the other packages. Starting Gold, roster and facilities must match the selected package.
3. Each new stable must open ready to play: Market shows actual offers, Finances shows treasury and initialized payroll, Championships shows eligible and locked events. Do not enable services, export a backup or invoke developer controls. No guide panel or extra Back/breadcrumb row should appear on management pages.
4. Roster & Barn: deactivate/reactivate driver/chariot; fill two beast slots. Activate a third beast, cancel and verify no change, then choose each replacement slot explicitly. Reload/Load Game and verify the accepted active selection. Names and conditions must remain readable.
5. Market: inspect cost and obligations on a recruit's card; choose a contract duration, Hire, review the same price/wages/duration and confirm. Buy a beast/chariot/equipment or staff where affordable and capacity permits. No separate Work Review page should be required. Cancel a confirmation and check no Gold/assets change. Unaffordable or capacity-restricted actions must explain the reason.
6. Workshop: inspect facility benefits, price and capacity, then purchase an affordable facility. Inspect engineering choices. Staff & Contracts must retain current and expired-contract decisions. Recovery & Services must own treatment/care/repair/training actions, with costs, effects and immediate completion disclosed. Training requires legitimately earned XP; do not expect free training. Finances must retain ledger, wages/debts and settlements, without a universal Work Review form.
7. Championships: resize wide and narrow; Events tiles should use multiple columns when space permits and one column on narrow screens, without horizontal overflow. Locked cards show precise qualification requirements. Select an eligible card without a charge. Details must show the complete schedule/awards; Registration must show the Barn selection. Return to Barn preserves the selected event. Confirm registration once; verify one fee and a frozen lineup.
8. Race: manually start. Confirm Play/Pause, speed, queued/active Strategy Signs, tactical map, standings and radio work. Single tick and Present buffered tail must be absent from normal controls. Open Options during playback: race pauses; return restores the prior play state. Help has six management topics and race guidance. Toggle alternate commentary OFF/ON and verify the native/alternate wording changes without changing race state.
9. Close the browser during an unfinished race. Reopen the same HTML and Load Game. Completed career decisions remain; the unfinished event restarts from its original seeded starting boundary. Do not expect mid-race continuation or restored unsaved Signs.
10. Finish a native race, return, select the existing Run Reward, manually start the next event, finish, confirm terminal settlement and choose the existing Legacy Reward. Check Last Event, official results and retained ownership. No duplicate reward, fee, payroll or settlement should appear after navigation or reload.
11. Navigate among every main page at least 20 cycles. No new service enablement, loading prompt, repeated continuation control or save confirmation should appear. No Save/Load destination belongs in main navigation. Go Race/Continue Championship remain shortcuts to Championships.
12. Options → Save & Load: Save Game must verify durable career decisions and explain that unfinished race progress is excluded. Verify Load Game between independent slots. Export career-only JSON and complete backup; confirm downloads actually exist on disk. Restore a complete backup into a separate clean browser/profile; verify identity, roster, team, preferences and progress. A backup for an existing identity must follow its confirmed own-career restore workflow. Never delete the only external copy during testing.
13. With a spare test career only, exercise confirmed career deletion and cancellation. Other careers must remain. Existing older careers must open without automatic upgrades or record loss. If an older career needs explicit compatibility/recovery, its controls are under Options → Save & Load → Recovery and older careers. Do not run a migration against the owner's only save without an external backup.

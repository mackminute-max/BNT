# Track test build — player instructions

1. Copy **only** `dist/Blood-and-Thunder-Track-Test.html` to your computer and double-click it. Choose a modern browser if Windows asks. No install, server, adjacent assets or network is required by the application. Keep the filename ending in `.html`.
2. For an oval, choose **Race format → Oval**, then Short Oval, Standard Oval or Grand Oval. Set laps and click **New race**. Standard Oval preserves the original track dimensions.
3. For a circuit, choose **Circuit**, select one of the twelve names, set laps and click **New race**. The paused preview uses the actual simulation geometry. Direction arrows, surface colours and the common start/finish line appear on the course.
4. For a Rally, choose **Rally**, select Short, Medium or Long, enter **Track seed**, terrain profile, turn frequency and complexity (both 0–1), then **Generate / preview**. Rally is one simultaneous point-to-point race; the lap control is disabled. The separate race Seed controls race randomness, not route generation.
5. Click **Start/Resume** for animation, **Step one tick** while paused, or **Run to classification** to complete the race quickly. Pure/Combat and weather remain available. The finish times lock at the line; finished units continue to clear the track.
6. Queue Strategy Signs before starting or during the race. Pre-race instructions activate at the signal. Later Rally signs activate at the next of three checkpoints, approximately 25%, 50% and 75%; the interface shows the next checkpoint. Later closed-track signs activate at the next start/finish crossing. The three-use limit is unchanged.
7. Expand **Developer tools → Track diagnostics** to inspect the track ID/name, seed/recipe, segments, distance, turns, terrain, width, validation result, race status and tick count. Diagnostics are a JSON block inside the existing developer panel. A generated fallback, if necessary, is explicitly identified here.
8. **Camera → Auto** follows the selected RU during long Rallies and shows an overview minimap. **Overview** fits the whole route; **Follow selected RU** follows the RU chosen in Derived performance inspection. Ready-state previews always show the whole route.
9. To reproduce a generated route, use the same Track seed, category, terrain profile, frequency and complexity, then Generate. For exact custom settings or future archival reproduction, export the full configuration from Developer tools; it preserves the complete route and generator recipe. Reproducing a race additionally requires the same race seed, weather, format, entrants, tuning and command schedule. Replay export preserves those inputs.

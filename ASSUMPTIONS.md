# Milestone 1 engineering assumptions

These are provisional engineering defaults, not approved final balance. All gameplay coefficients live in `src/config/config.js`; `config({ tuning: {...} })` permits validated weight overrides. `rules` lists scalar bounds and units. Tuning values have bounds 0..2, impairment and speed-floor fractions 0..1, ordered coordination limits, and normalized handling/control/combat weight groups. Structural edits require a new race. The M1 UI inspects derived values; full editing is M2/M4 work.

## Milestone 2 additions (supersede M1 reference-driver scope above)

The default run now uses autonomous drivers; `driverMode: 'reference'` remains an explicit regression-fixture option. Personality consists of six validated 0–100 tendencies. Omitted personality values use a deterministic stable-ID-derived engineering fixture profile, with no lore implied. `src/ai/weights.js` centralizes validated utility, perception and traffic thresholds; `autonomous.utility` supports overrides (each finite 0..100). `src/sim/environment.js` centralizes autonomous tuning, exertion rates and all five static weather presets.

- Strategy evaluation defaults to every 10 ticks; perceived tactical danger is checked every tick. Movement blockage, control changes and sign activation trigger within-tick reconsideration after their simultaneous physical group. Seeded draws include subsystem, RU, tick and evaluation number.
- Utility scores are additive and separately select compatible pace and position/racecraft. The position layer can request hold, inward/outward, overtake, defend, yield or avoid. Yield maps to Conserve. Hold/defend retain the current line; overtakes/avoidance choose a legal perceived adjacent opening. Authoritative physics can reject an intention even when the driver could not perceive the obstruction.
- Perception uses tile distance, Awareness and weather visibility, not the full authoritative scene. These provisional visibility defaults are omnidirectional within that range; occlusion and a visual cone are not specified. Hidden entries never enter candidate scoring or diagnostics. Errors separately represent missed danger (judgment), failure to execute (Driving), and stress-related failure (Nerve/strain/control state).
- Goals receive a configurable switching bonus. Successful lane changes impose `goalTicks` (default 30) of lateral cooldown. An overtaking driver avoids returning into the passed driver's lane until sufficient perceived clearance. These decisions reduce oscillation without granting movement immunity.
- Five weather presets are static per race. Grip alters acceleration, braking and cornering; rolling resistance alters speed; visibility alters perception; heat/weather alter fatigue and recovery. `surfaces` overrides (by segment ID) validate grip/rolling resistance 0.1..2 and roughness 0..2. Surface changes affect subsequent physical subintervals.
- Fatigue integrates separately per beast over actual elapsed subintervals. Generation depends on exertion, Endurance, overload, weather, roughness and condition. Recovery applies only below `recoveryThreshold` (default 0.6). Driver strain and chariot wear accumulate separately. Bounds remain 0..100. Derived impairment is refreshed at tick boundaries and tile crossings; physical targets are recomputed after subevents. No double integration per subevent.
- Six signs share the approved queue/replace/cancel/lower rules. `issueSign` applies a command at the current resolved boundary without advancing the clock, recording its exact order. A pre-race queue activates at the starting signal; later queues activate at the next physical forward line crossing. Cancellation never refunds, and lowering is free. Signs cannot directly modify physical attributes.
- Global and per-sign utility strengths are configurable. Tactical Discipline scales responsiveness. Diagnostics distinguish Followed, Partially Followed, Overridden, Inapplicable and Prevented, with candidate terms, perceived state, choices and error flags. Engagement is legal to queue in Combat but remains Inapplicable until M3 supplies actual legal combat candidates; it is rejected without charge in Pure.
- Tuning is applied only when creating a new race. The current UI exposes weather/format, fatigue rate, sign strength, utility-noise/error rates and six per-sign weights; full individual/bulk editing, live overrides, storage and replay UI remain M4. Existing input/event export and headless reconstruction include weather, tuning, surfaces and ordered sign commands.

All rates/weights are provisional, not final balance. Autonomous scalar tuning accepts finite 0..100, with integer decision/goal ticks (>=1), integer sign allowance (>=0), and probabilities/recovery threshold limited to 0..1. Existing M1 physical configuration bounds continue to apply.

## Milestone 3 additions (supersede earlier deferred-combat/contact statements)

The default application now enables combat legality, physical contact damage, component targeting, control consequences, persistent wrecks and optional incidents in the one authoritative simulator. `src/sim/consequences.js` centralizes the complete provisional `consequenceDefaults` table and validated overrides. M1's `consequences: false` setting exists only for explicit movement-only regression fixtures; M2 and new M3 integration scenarios run with consequences enabled. `driverMode: 'reference'` alone does not disable damage.

| Choice | Default and rationale | Validation / effect |
|---|---|---|
| Contest | Attack = derived combat × 1.2 + bounded ±8 noise. Defense combines Driving (0.4), derived Combat (0.4), Control (0.2), optional reaction (+10) and selected combat defense (+12) | T11; margin > 0 succeeds. No guaranteed hit from a sign. Weights/strength/noise configurable |
| Initiative | Same-time attacks ordered by seeded tick/attacker priority; stable ID breaks a hash tie. Effects apply immediately before the next attack; disabled/finished/out-of-range/cooling actors invalidate | Permutation and lethal-invalidation tests; no entrant-array-order priority |
| Range/cooldown | Close attack within 1.25 tile cross-sections and at most one adjacent lane; ram within 0.75 tile and exactly one adjacent lane. 1.2 s cooldown | Geometry is checked again at execution. No attack is legal in Pure; no deliberate attack targets finishers or wrecks |
| Reactions | One reaction per RU per tick; reset once at tick boundary, shared across all subevent calls. Out-of-control drivers cannot react. Selected combat defense adds its bonus only when a reaction is available | Cross-phase budget, defense and eligibility tests |
| Utility | Aggression/opportunism encourage attack/ram; caution encourages defense/disengagement. Engage Rivals adds the existing sign preference only when a legal perceived target exists | New combat weights centralized in consequence configuration. Combat and lateral movement are incompatible intentions for one selection |
| Impact energy | Abstract `0.5 × effective mass × relative speed²`. A stationary wreck has effectively infinite opposing mass. Front/side/rear geometry factors default 1/0.6/0.7 | Physical impact remains separate from attack contest margin; values are not calibrated joules |
| Lateral impact | Incidental side attempt adds a 1.5 m/s lateral component when moving; a successful deliberate ram supplies a 5 m/s lateral impulse | Configurable approximation for discrete adjacent lane interactions; no displacement of wrecks |
| Component damage | Physical damage scale 0.003; margin-based close-attack damage 7 × bounded success multiplier. Protection, per-component resistance, grip and derived collision resistance reduce damage | Driver/chariot/individual beast conditions clamp to 0..100 and immediately refresh performance. Weapon damage is separate from the physical damage scale |
| Exposure | Front weights beasts/driver/chariot = 4/0.5/1; side = 1/2/4; rear = 0.5/1/5; close attack = 1/3/1. Team beast weight is divided across individuals | Direction and deterministic contact/RU key select the component. Weights are configurable; zero-total direction weights rejected |
| Simultaneous physical groups | Record source velocities before resolution; calculate damage using pre-effect resistance; accumulate damage/shock before refreshing/retiring affected RUs | E03 and permutation tests. Saturation/overkill attribution follows deterministic contact IDs; total physical result is independent of entrant storage order |
| Movement conflict vs impact | A rejected lateral reservation is not automatically a physical impact. If the initially occupying RU successfully vacates, rejection emits a movement-conflict record without damage | Explicit vacating-reservation regression. Swaps still reject crossed swept paths; genuine physical contacts may damage |
| Control | Instability >15 = Unstable; >40 = Out of Control; ≥100 = Disabled. Damage and energy add shock; corner overspeed can add shock. Recover at 5 units/s | Physical clock includes threshold crossings. Out-of-control target speed is zero with actual braking, not teleporting or an immediate speed reset. Disabled is permanent for the race |
| Disablement | Driver/chariot condition ≤5, all beasts condition ≤10, or instability reaching the disabled threshold retires an unfinished RU | Conditions and thresholds configurable. One impaired beast affects team performance but does not automatically retire an otherwise functioning team |
| Wrecks | Retire at final legally resolved position, speed zero; retain lane/tile occupancy and an invariant-checked anchor through race end. Secondary impacts never move/despawn the wreck | T12–T15, E06/E07/E16. A finisher physically disabled while clearing becomes a wreck but retains its locked official classification/time |
| Repeated contact | Continuous side contact and low-speed stationary retries do not reapply damage. A renewed forward closing speed above 0.75 m/s, separation/re-contact, or a new deliberate ram can create a new contact ID | T14/E05. IDs link physical/attack/incident effects to damage and retirement. No arbitrary contact-damage timer |
| Chain budget | At most 128 physical/weapon impact entries per tick, plus existing chronological subevent budget | Overflow stops with an explicit integrity error; never silently drops queued work |
| Incidents | Exponential waiting clock, rate 0.002 per simulated second; weighted debris/animal/spectator = 6/2/1; duration 12 s. Minimum random interval 0.1 s | Not mandatory every race. Placement excludes occupied cells, existing hazards, finish/exit tiles. Scheduled requests use the same eligibility checks |
| Incident consequences | Active hazard tiles block swept entry, cause a bounded new impact, and can be avoided/braked for according to filtered perception. Hazards expire on the physical clock; wrecks do not | Placement/expiry/high-speed impact tests. Mass defaults debris/animal/spectator = 20/100/70 kg for the abstract impact formula |
| Stall administration | Existing no-progress and race-time limits now retire remaining Racing RUs with explicit safeguard reasons and create persistent wrecks before reporting Stalled | T15/E07; no fabricated finish. Already locked finish classifications remain unchanged |
| Event records | Copy effect data when emitting; later diagnostics cannot rewrite prior events. Explicit execution-result events report invalidated or prevented actions | History immutability and exact replay tests |

Consequence scalar values must be finite 0..10000; reaction budget and chain budget are integers (chain ≥1), probabilities remain in their earlier domains, speed-retention fractions are 0..1, condition thresholds ≤100, control thresholds strictly ordered, control recovery positive, attack ranges/cooldown and incident duration/interval positive, and incident rate ≤1. Directional component/incident weight groups require positive total weight. These are engineering validation limits, not recommended balance ranges.

M3 presentation adds wreck crosses, incident markers, DNF rows/reasons, conditions/control inspection, attack/damage/wreck/incident counts and new-race physical damage/incident controls. Full commentary, persistence, replay UI, comprehensive developer editing/live overrides and final crowded-exit acceptance remain M4 work. The direct offline `file://` browser gate remains blocked by the managed browser policy; HTTP diagnostic checks are never treated as passing that gate.

## Milestone 4 additions and final prototype decisions

These supersede earlier statements deferring commentary, replay, persistence, developer editing and crowded-exit work.

- **Commentary provenance:** copied authoritative events drive a separate commentary adapter. Text variation hashes event IDs and never consumes simulation RNG. Ordinary repeated categories use a one-second simulation-time cooldown; finish/retirement/final-lap/lead/sign/integrity events bypass that cooldown. Commentary does not infer outcomes from renderer positions. Attack/wreck events explicitly identify the attacker, defender or wreck rather than relying on alphabetically sorted participants.
- **Racecraft records:** overtakes and unambiguous leader changes are authoritative observations emitted at resolved tick boundaries. Overtake records label that observation timing. They do not feed back into physics. Completed finish order always uses precise locked timestamps.
- **Crowd:** weather/environment tuning includes `crowdMorale` (0.1..3, neutral 1). The configurable model coefficient `crowdSensitivity` defaults to 0.2 (0..1). The control multiplier is `1 + (crowdMorale - 1) * (1 - Nerve/100) * sensitivity`, with final Control clamped 0..100. Nerve buffers the performance effect. Crowd never directly damages/interferes with an RU; explicit recorded spectator incidents remain the sole intrusion route.
- **Continuous braking:** corner approach uses an analytic event for intersection with the braking envelope. After reaching it, braking targets the future safe speed, not the repeatedly shrinking instantaneous envelope. No braking coefficient or safety-budget increase was used to conceal the seed-3 event-cascade defect found in the first reference batch. Both formats now complete that regression normally. Pre-fix evidence is archived as such.
- **Clearing safety:** finished units remain physical and brake for occupied cells on the exit approach. Clearing uses an administrative occupancy controller, not competitive overtaking/combat. Each lane has an exit mouth. Closely queued eight-finisher and blocked-exit cases verify legal occupancy, locked official times and persistent wrecks. A physically blocked exit may still trigger an explicit safeguard rather than teleporting an entrant.
- **Live overrides:** only validated supported numeric fields at a paused resolved boundary. Geometry/layout, clock/subevent constants, laps and sign allowance require new-race setup. Commands queue without changing the physical state, apply at the next tick, increment a configuration revision, and record tick/time/order/version/target/path/old/new. Bulk RU edits form one revision. Reaction-budget edits take effect at that boundary; incident-rate edits rearm the deterministic incident clock. Existing cooldown deadlines remain historical state, not retroactively shortened.
- **Component scope:** `all` is reserved for bulk editing. Wildcard `beasts.*` edits every beast; a specific missing team index is ineligible in bulk scope. Input schemas reject unknown attributes/equipment effects, nonfinite values and invalid ranges. A live edit cannot reanimate or delete a wreck.
- **Presentation transport:** Start/Pause/Speed/Step request whole fixed simulation ticks. Normal frame deltas cap at 0.25 s to avoid wall-clock catch-up bursts; physics never reads those deltas. Tests at 30 and 144 FPS produce identical results. Fast-forward and replay verification yield in 100-tick chunks; pause/new-race/import cancels the old presentation transport without changing a resolved authoritative tick.
- **Replay:** schema 1, exact simulation version, immutable original setup/initial RNG, ordered commands, copied events, periodic checksums and final checksum/endpoint. Default checkpoint period 100 ticks (1..10000). Missing/duplicate/corrupt checkpoints, changed events and final-state mismatch are errors with first-divergence context. No event-only fallback. Pending edits and final paused signs survive partial capture; interactive replay is read-only and reconstructs states through the same engine.
- **Persistence:** optional localStorage key `bnt.configuration.v1`, versioned/validated before use. Failed access/write never changes valid in-memory state or blocks races/exports. Saving uses the explicit configuration editor; capturing current components/tuning is a separate labeled action. No implicit save migration or cross-browser/file-path save sharing is assumed.
- **Batch/reporting:** the same engine and input rules, 1..1000 seeds per request, cooperative cancellation retaining completed samples. Official tied winners each receive a winner count. Fatigue-at-finish averages actual finished beasts; absent data is not fabricated. Sign compliance tracks the correct decision/execution sample and never rewrites an earlier sign sample after lowering. No target win rate or final lethality balance is asserted from the reference samples.
- **Inspection:** primary/secondary derived values, normalized component/personality inputs (mass/capacity keep their units), aggregation/effective inputs, mass/load, weather/surface/model modifiers, AI score/error details and override history are visible. Full configuration JSON handles coordinated schema edits; numeric controls cover supported parameter groups and live editing.

The final release gate remains actual direct offline file execution. Static embedding checks and HTTP diagnostic tests are not treated as substitutes. Historical M1–M3 reports and the pre-braking-fix M4 report describe earlier artifacts, not the final build.


## M4 audit remediation — 0.4.1-m4

- Active incident tiles block lateral reservations as well as forward traversal, independent of perception. A rejected lateral incident entry queues a side-direction physical impact at the current subevent time using the existing mass/speed/damage model and contact deduplication. Shared impact flushing precedes continued movement; no new balance coefficient or direct player steering is introduced.
- Sign compliance evaluates the actual pace after a yield/disengage override. Diagnostics preserve the selected candidate and explain its replacement; autonomous caution is not an execution error or guaranteed sign obedience. Physical execution failures retain their Prevented classification.
- Seed range endpoints must be safe integers. Every token is counted against the 1000-seed request bound before expansion. Invalid input rejects without changing the viewer race. Safe-integer endpoints are permitted, including the upper boundary; ranges use bounded offsets rather than an endpoint increment that can stop advancing.
- The simulation version advances to 0.4.1-m4 because authoritative diagnostics and incident events change. Replay schema remains 1; prior-version replay records are explicitly rejected, with no implicit migration. Configurable balance defaults are unchanged.


## Corrective maintenance — 0.4.2-corrective

These entries supersede the earlier diagnostic and verification notes where applicable; unrelated numerical defaults are unchanged.

- **Action reporting:** AI selection remains unchanged. Intended candidates, effective issued preferences, physical outcomes and sign compliance are separate diagnostic layers linked by decision ID. Pending positional compliance is null until resolved; only the existing five finalized categories are used. An unrelated lane/combat failure cannot invalidate pace compliance. A blocked forward path can prevent Push achievement, and control loss can prevent pace execution. Linked final results drive technical/batch counts; immutable decision events retain their original intent-time state.
- **Paused signs/replay:** direct paused sign controls retain immediate behavior and now record their paused command phase, reconstructed before boundary condition/retirement effects. This ordering is required by the discovered queued-sign/initial-wreck replay case, not a change to sign allowance or activation rules.
- **Segment hazard placement:** hazardModifier is a dimensionless per-segment weight, default 1, validated 0..2 and exposed to developer setup. Positive weights select among otherwise legal placement cells using the existing single seeded draw. Zero excludes cells, including explicit scheduled placement. Global random frequency/type weights, cooldown, duration and all other incident coefficients remain unchanged. Zero random rate disables random incidents; intentionally scheduled test incidents continue to obey eligibility. consequences=false disables both. Neutral weights preserve the prior uniform placement and RNG consumption. These values remain provisional/configurable.
- **Historical fatigue:** the qualifying finish captures full-precision time and per-beast fatigue in a deeply frozen, nonreplaceable finishSnapshot. Snapshot time/fatigue is historical data, independent of mutable current fatigue, component edits, post-finish clearance and result export copies. It enters events/state checksums/replay and supplies technical/batch fatigueAtFinish.
- **Photo fixture:** fixture-only rollingEfficiency=57.34996687475359 for outer-lane B compensates longer physical distance and gives a roughly 0.0005-second gap in the controlled reference-driver scenario. Production tolerance remains 0.001 and all race-distance/timestamp rules stay unchanged. A tighter configured tolerance splits the finishers without moving either timestamp.
- **Offline evidence:** the owner confirms local offline operation of the pre-corrective 0.4.1 file. Managed Chromium still denies file navigation; HTTP diagnostics are separate. The new 0.4.2 artifact is not yet owner-confirmed or independently direct-file tested here, and final owner acceptance is not inferred.
- **Versioning:** authoritative event/state changes require simulation 0.4.2-corrective, package 0.4.2. Configuration and replay remain version-specific (schema 1); no automatic reinterpretation of older replays is attempted.
